## How to read coverage

| Label | Meaning |
| --- | --- |
| Covered | The inspected material explicitly explains or demonstrates this capability. This is a coverage judgment, not proof that it works in production. |
| Partial | A brief mention, illustrative example, subset, older UI, or limited setup aid exists; the missing part is stated. |
| Not found | No relevant coverage was located in the inspected source set. This does not establish absence everywhere. |
| Unknown | The relevant deployed behavior, private material, or downstream service could not be established by this audit. |

**Source only** means code and documentation were inspected, without fresh execution of that feature. Tests cited below were read as evidence of intended behavior, not run. **Artifact metadata** means a file or recorded release result exists, not that this audit repeated its verification. **Scripted** and **concept** demonstrations must not be read as recordings of successful live agent work. An ordinary button, tooltip, or settings panel is not automatically onboarding; limited explanatory setup flows are marked Partial.

Landing references L1–L6, demo references D0–D6, and onboarding references O0–O4 resolve in the dated source register below. A bare **Not found** in a landing or demo cell refers to that inspected register; O0 records the app search boundary.

## Consequential coverage gaps

These are observations for launch planning, not an approved implementation backlog.

1. **First-use proof is missing from this audit.** No clean friend-like install, first authenticated conversation, or no-Beads onboarding was executed. Existing notarized-release metadata is useful evidence, but does not establish that an invited download contains today's source or works on a fresh Mac (F05, F51–F53, F60).
2. **The app has setup aids, not the requested onboarding demo.** Project selection and device setup are visible, but no feature tour/embedded teaching flow was found (F63). Website samples and developer demo scripts must remain separately classified.
3. **The cross-provider differentiator is underexplained.** The landing page names Codex/Claude coordination; it does not clearly teach Claude creating a Codex agent, or cover Google/Kimi. Existing cross-provider films simulate an OpenAI-led team (F13–F14, F26).
4. **Demo availability exceeds public discoverability.** One general film and five focused/concept films exist locally. No links to those videos were found in the fetched landing page. Most focused films teach dispatch/orchestration; many practical first-use features have no demo (F61–F62).
5. **Managed hosting is a stronger claim than the inspected evidence supports.** The live page describes it, while this repository supplies a proposal and a working-source path for private access to one's own machine. A separate deployed service remains Unknown (F54, F59).
6. **Notification setup needs to match the intended beta.** Desktop alerts, Home Screen Web Push, and native APNs have different prerequisites. Native push currently assumes operator-controlled signing credentials; public customer-Mac push distribution is not solved by the existing source (F22–F24, F56).
7. **Attention and continuity need current demonstrations.** Jev is optional, source is changing, and the older general film has a different project/view model. Current source supports same-thread scheduling, while historical notes described new-thread-only behavior. A release-specific check would resolve what friends actually receive (F03, F17–F21, F46, F50).
